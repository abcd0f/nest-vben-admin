# 阶段 1：离线准备

本轮只准备代码并使用隔离数据库验证，未修改当前数据库。2026-10-16 重新读取当前九表，全部为零行，因此没有现存 ID 或关联要转换。若在正式切换前新增了任何行，`migration.sql` 会在事务开始时拒绝执行；不能把数据静默归入默认租户，也不能丢弃旧 ID。

`migration.sql` 由阶段 0 冻结的 PostgreSQL 九表 DDL 组成，执行前要求九表为空。它暂存于此，不在活动的 `prisma/migrations` 中：当前认证、权限和五个管理服务仍使用旧 Prisma 模型，提前部署目标结构会使服务不可用。后续阶段完成目标服务实现并验收后，须把同一份 SQL 作为新的 Prisma migration 激活，再整体切换应用与数据库。不得把本目录直接用于当前数据库的 `prisma migrate deploy`。

五个现有创建路径已显式调用雪花 ID 生成器，使用与目标 ASSIGN_ID 相同的 epoch 和 41 位时间、5 位数据中心、5 位 worker、12 位序列。每个实例须设置 `SNOWFLAKE_DATACENTER_ID` 和 `SNOWFLAKE_WORKER_ID`，取值均为 0 至 31；同一时刻运行的实例不得复用同一组值。未配置时创建操作会拒绝执行。ID 始终以 `bigint` 写库，以十进制字符串出现在 HTTP 响应中。

隔离库验证命令：设置 `RUOYI_DATABASE_URL` 后执行 `pnpm test:ruoyi-phase1`。测试从冻结的历史迁移建立旧结构，再执行待切换 SQL，与目标 schema 快照逐项比较，并验证非空数据时事务回滚。当前验证结果为目标差异 0、非空输入拒绝且原始 BIGINT 行保留；`pnpm build` 和 `pnpm test` 通过。

阶段 1 尚未完成：目标 Prisma 模型及业务服务必须与后续阶段一同替换，正式迁移还需维护窗口、停写、快照/恢复演练和最终数据盘点。此处没有宣称当前数据库已经切换。
